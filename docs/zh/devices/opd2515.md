## 固件与启动 {#firmware}

`device-verified`

组件: `XnuPrelink`, `DarwinBoot`.

### 硬件与依赖

- Stock GBL/BDS fastboot environment, a valid boot image generated by the device package, and Apple-derived payload inputs supplied locally.
- DarwinBoot and a bundle-format trust cache for XNU 8796 iOS 16.5.

### 配置

- The payload uses volume OPD2515, a 208 MiB FAT image and one DarwinBoot driver entry.
- The boot image uses header version 0, 4096-byte pages, base 0x10000000, kernel offset 0x8000 and tags offset 0x100.

### 操作步骤

- Build the OPD2515 package, verify every payload member and boot-image segment, then use fastboot boot only.
- After each run, enter OrangeFox/REC and read the authorized userdata-tail log without formatting userdata.

### 开发经验

- BDS discards the Android boot-image ramdisk, so the EFI application scans the retained fastboot buffer and republishes it as a block device.
- DarwinBoot path LoadImage was denied by Security2; loading from a private memory buffer while retaining firmware Security2 validation succeeded.

### 完成条件

- BDS enumerates the image, executes UniXNU, loads DarwinBoot and reaches the kernel handoff with no signature error.
- The latest source revision is retested on hardware after any rebase.

### 当前范围

- S8 is device verified from the pre-rebase image. The S9 stage-3 image is host verified only.
- No firmware partition may be modified.

### 下一步

- Boot the S9 image once in BDS and record whether the green, blue and magenta checks are followed by a reset after about six seconds.

## 诊断 {#diagnostics}

`device-verified`

### 硬件与依赖

### 配置

- DarwinBoot and the kernel entry probe provide green, blue and magenta checkpoints.
- S9 enables only the official stage-3 reset probe with a six-second delay after the MMU-enable instruction.

### 操作步骤

- Capture screen and photos, then read the exact userdata tail through REC after each failed boot.
- Record timestamp, last UNIXNU/DARWINBOOT lines and whether the screen reset, returned or stalled.

### 开发经验

- S8 reached DarwinBoot handoff and the magenta entry checkpoint, then a new UniXNU menu appeared without a confirmed timing cause.
- S9 reached the same green, blue and magenta checkpoints and then hard-reset after a user-observed delay of several seconds; exact timing was not measured.
- After the S9 reset, Android reported ro.boot.bootreason=reboot, on OPD2515.

### 完成条件

- A reproducible command, source/image revision and accessible result accompany every claimed hardware milestone.

### 当前范围

- No serial console is available and the XNU path cannot use EFI services after boot-services exit.
- The S9 hard reset is a preliminary MMU-post-enable result, but the exact magenta-to-reset interval remains unknown.

### 下一步

- Repeat S9 unchanged with a stopwatch or video. If reset occurs at about six seconds, mark stage 3 final and test stage 4 after \_arm\_vm\_init in \_arm\_init.
